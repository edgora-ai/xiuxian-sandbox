# 08 · 技术方案与路线图

> 目标形态：**浏览器即开即玩的体素沙盒**（PC Web 优先，后续打包移动端），离线可玩，存档本地 + 可选云同步。
> 我们已在 red-alert 项目验证了"纯逻辑 sim + Three.js 渲染 + 零依赖离线"的架构路线，本项目沿用并升级。

## 1. 技术选型

| 层 | 方案 | 理由 |
|---|---|---|
| 渲染 | Three.js（WebGL2）+ 自研贪心网格体素渲染器 | 沿用已有经验；体素贪心合并 + 面剔除，目标 8~12 视距区块 60fps |
| 逻辑 | 纯 TS/JS 模拟层（零 DOM 依赖），固定步长 tick | 可无头测试、可做服务端权威（未来联机） |
| 世界生成 | 种子化噪声（生物群系/灵脉/洞窟）+ 分层结构（遗迹/秘境） | 可复现、可分享种子 |
| 存档 | 区块差分存档（只存修改）+ IndexedDB 本地；导出 `.dongtian` 单文件 | 体素存档体积可控，玩家可分享 |
| 资源 | 全程序化生成（纹理/模型/特效/音频），与 red-alert 同路 | 零素材成本、风格统一、包体小 |
| 联机（后期） | 权威服务端 tick 同步，参观/合作建造优先 | 先单机后社交 |

## 2. 客户端架构

```
src/
  sim/          世界数据(区块/实体/方針)·物理·成长·妖兽AI·阵法逻辑（零 DOM）
  render/       体素网格器·角色/妖兽卡通模型·粒子特效·后处理(Bloom/软雾)
  ui/           玉简HUD·四艺工坊界面·阵法拼图编辑器·图鉴
  audio/        WebAudio 程序化仙乐与音效（笛/古筝/玉磬）
  net/          (后期) 会话同步
```

关键子系统：
- **体素渲染**：16³ 分块贪心合批 + 顶点色 AO + 程序纹理图集；卡通描边用后处理边缘检测
- **阵法逻辑**：阵基注册为"功能区节点"，调度器按灵气池预算执行（红石等价物，tick 驱动）
- **成长系统**：修为/境界/功法纯数据表驱动，热更新内容（09 数据表即初始版本）
- **性能红线**：中端手机 30fps / 桌面 60fps；首屏加载 <8s（程序化生成优势）

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 体素渲染性能 | 贪心网格 + 区块 LOD + 视距自适应；粒子硬预算 |
| 内容量需求大（沙盒劝退） | 数据表驱动 + 每境界 1 次内容扩容节奏；早期靠"四艺×阵法×驭兽"系统深度撑玩法 |
| 修仙题材同质化 | 差异点=真正的自由建造+阵法自动化（市面上修仙游戏几乎不做创造） |
| 联机复杂度 | 单机优先，联机只做参观/合作建造，不做全服对抗 |
